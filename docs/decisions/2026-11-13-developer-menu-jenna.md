# Menu Developer: Ringkasan Sistem & Pengaturan Jenna

Tanggal: 2026-11-13 · Versi: 0.1.277 · Migrasi: `20261113100000_jenna_settings` (additive: `JennaSettings`, `JennaProvider`)

## Konteks
Jenna (asisten AI desa) butuh tempat untuk mengatur provider AI (base URL, model, API key) dan batas pemakaian tanpa redeploy. Mengatur lewat env berarti setiap ganti model/key harus edit env stack + restart container, dan tidak ada tes koneksi. Developer juga tidak punya satu halaman untuk melihat kondisi runtime (versi yang aktif, koneksi DB/MinIO, env mana yang belum diisi) tanpa masuk ke server. Role DEVELOPER ("0") sudah ada dan kini bisa diberikan lewat `DEVELOPER_EMAIL` (0.1.277), tetapi belum punya menu khusus.

## Keputusan
- **Lokasi `/dev/*`: Developer Console terpisah dari `/admin`**, dengan layout sendiri (`src/app/dev/layout.tsx` → `_com/DevConsoleShell.tsx`): header "Developer Console" + badge `NODE_ENV` + versi, navbar Ringkasan Sistem + grup Jenna (Umum / Batas Pemakaian / Provider), tautan "Buka Admin" (ke `ADMIN_HOME_PATH`, bukan `/admin` root) dan "Website Desa", menu akun + logout, burger di mobile, mengikuti token tema admin (`themeTokens`, store `darmasaba-admin-dark-mode`). Halaman: `/dev/ringkasan`, `/dev/jenna` (Umum: status + identitas & persona), `/dev/jenna/batas`, `/dev/jenna/provider`; `/dev` redirect ke `ringkasan`. Sub-halaman Jenna berbagi `jenna/layout.tsx` (muat config sekali, header, Muat ulang, peringatan kunci enkripsi) supaya pindah sub-halaman tidak fetch ulang; tiap bagian tetap disimpan sendiri lewat API yang sama. Pindah halaman lewat navigasi konsol saat ada draf belum disimpan meminta konfirmasi (`useLeaveGuard`), selain `beforeunload` untuk refresh/tutup tab. State Valtio di `src/app/dev/_state/` (pola `_state` admin, berdampingan dengan pemakainya). Yang dipakai bersama admin hanya sesi Better Auth, token tema, komponen `UnifiedSurface`, dan `logoutAndRedirect` (`src/lib/client-logout.ts`). Alasan: alat developer (infrastruktur, provider AI) berbeda audiens dan risiko dari CMS konten; konsol terpisah membuat batasnya jelas, tidak ikut sidebar 2 level admin, dan bisa tumbuh (log, statistik Jenna) tanpa menambah menu admin.
- **Masuk**: login role "0" langsung ke `/dev` (`defaultRouteForRole`). Role 0 tetap admin, jadi `/admin` tetap bisa dibuka; sidebar admin role 0 punya satu item "Developer" → `/dev`. Redirect `/admin` root per role (`getRedirectPath` di `src/app/admin/layout.tsx`) sengaja tidak diubah supaya "Buka Admin" tidak memantul kembali ke `/dev`.
- **Hanya role "0".** `isDeveloperRole` (`src/lib/auth-policy.ts`) dipakai di empat lapis: proxy (`/dev/:path*` di matcher, `decideDevAccess`: tanpa sesi/nonaktif → `/login`, role admin lain → `/admin`, user biasa → `/profile`, cache miss + token → lolos ke lapis berikut), layout `/dev` (muat `/api/auth/me`, keputusan yang sama; children & fetch API developer tidak jalan sebelum role 0 terkonfirmasi), sidebar admin (`developerMenu` ditambahkan `getNavbar` hanya untuk role 0, sengaja **tidak** dimasukkan ke `navBar`/`devBar`/role arrays supaya tidak bisa diberikan lewat Menu Access), dan API (setiap handler `requireDeveloper` → 401 tanpa sesi, 403 bukan developer). `/api/developer` juga masuk `ADMIN_ONLY_GET_PATHS` di guard global sebagai lapis tambahan, karena GET di project ini publik secara default.
- **API key provider disimpan di DB, terenkripsi AES-256-GCM** (`src/lib/jenna/crypto.ts`, `node:crypto`, format berversi `v1:iv:tag:ct`). Kunci dari env `JENNA_CREDENTIALS_KEY` (64 hex), opsional agar app tetap boot. Fail-closed: tanpa kunci valid, simpan API key ditolak, tidak pernah jatuh ke plaintext. API key tidak pernah dikembalikan API; respons hanya `hasApiKey` + `apiKeyHint` (4 karakter terakhir). Field API key kosong saat simpan = pertahankan key lama.
- **Tes koneksi dari server**, memakai key tersimpan: OpenAI-compatible `GET {baseUrl}/models`, Anthropic `POST {baseUrl}/v1/messages` (`max_tokens: 1`). Timeout per provider, `redirect: "manual"`, pesan galat disanitasi. Base URL wajib https; http hanya untuk localhost/127.0.0.1 di luar production; kredensial/query/hash di URL ditolak.
- **Ringkasan Sistem read-only**: versi (`package.json`), `NODE_ENV`, uptime, ping DB & MinIO + latensi, kesiapan Jenna, dan checklist env berdasarkan allowlist nama (hanya `set`/belum, nilai tidak pernah dikirim).
- **Scope tahap 1: pengaturan saja.** `JennaSettings` (singleton `id = 'global'`) + `JennaProvider` (PK slot `chat_openai` | `chat_anthropic`). Tidak termasuk runtime chat, voice, statistik pemakaian, error log, maupun riwayat percakapan. Kolom batas (rate limit, kuota harian, retensi) disimpan sekarang supaya runtime tahap berikutnya tinggal membaca.

## Alternatif yang ditolak
- **Konfigurasi provider lewat env** (`JENNA_API_KEY`, `JENNA_MODEL`, …): setiap perubahan butuh edit env + restart, tidak ada tes koneksi, dan developer tidak bisa mengubahnya dari admin.
- **API key plaintext di DB**: backup/dump DB atau akses baca DB langsung membocorkan key provider berbayar.
- **Menu di bawah Pengaturan (role 0/1)**: SUPER ADMIN tidak perlu mengatur provider AI atau melihat detail infrastruktur; memisahkan section menjaga Pengaturan tetap untuk konten.
- **Developer sebagai section Menu Access biasa**: section di `navBar` bisa dicentang untuk role mana pun lewat halaman Menu Access, sehingga gating role bisa terlewati tanpa sengaja.
- **`/admin/developer/*` di dalam layout admin** (keputusan awal di branch ini, diganti sebelum rilis): alat developer bercampur dengan CMS konten di sidebar yang sama, terikat pola sidebar 2 level admin, dan developer harus melewati dashboard konten dulu. Auth dan tema tetap bisa dipakai bersama tanpa berbagi layout, jadi duplikasinya kecil (guard sesi ringan + shell).
- **Aplikasi terpisah (repo/deploy sendiri)**: menduplikasi auth Better Auth, DB, dan pipeline rilis tanpa manfaat untuk dua halaman.

## Konsekuensi
- Route: `/dev`, `/dev/ringkasan`, `/dev/jenna`, `/dev/jenna/batas`, `/dev/jenna/provider` (tidak ada redirect dari `/admin/developer`: belum pernah dirilis).
- API: `GET /api/developer/system`, `GET /api/developer/jenna`, `PUT /api/developer/jenna/settings`, `PUT /api/developer/jenna/providers/:slot`, `POST /api/developer/jenna/providers/:slot/test` (`src/app/api/[[...slugs]]/_lib/developer/`). Format galat seragam `{ success: false, message }`.
- Operator: generate `JENNA_CREDENTIALS_KEY` sekali per environment (`openssl rand -hex 32`). Mengganti/menghapus kunci membuat API key lama tidak bisa didekripsi: tes koneksi gagal dan key harus diisi ulang. Detail di `docs/DEPLOYMENT.md`.
- Tahap berikutnya (tugas terpisah): runtime chat Jenna yang membaca `JennaSettings`/`JennaProvider` dan menegakkan batas pemakaian, lalu voice dan statistik.

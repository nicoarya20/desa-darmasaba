# Sampah (trash) berkas & dokumen semua menu

Tanggal: 2026-11-12 · Migrasi: `20261112210000_sampah_file`

## Keputusan
- **Hapus berkas = pindah ke Sampah, terpusat.** `removeStoredFile(file, owner)` (`_lib/fileStorage/_lib/removeStoredFile.ts`)
  kini hanya mengisi `FileStorage.deletedAt`, `isActive=false`, dan `deletedFrom` — baris & objek MinIO **tidak** dihapus.
  Semua handler yang dulu menghapus langsung (`minio.removeObject` + `fileStorage.delete`, ±38 handler del/updt,
  Maskot, Profil PPID, `DELETE /api/fileStorage/delete/:id`, `DELETE /api/img/:name`) dialihkan ke helper ini. Data
  utama (berita, potensi, dst.) tetap terhapus seperti biasa; yang berubah hanya nasib berkasnya.
- **Urutan aman:** berkas dipindah ke Sampah **setelah** operasi DB record sukses. Handler yang dulu menghapus berkas
  sebelum update/delete record diperbaiki urutannya (pola bug Maskot). Update gagal → berkas lama tetap aktif.
- **Berkas yang masih dirujuk tidak masuk Sampah.** `isFileReferenced` (`fileReferences.ts`) membaca semua FK yang
  merujuk `FileStorage` dari katalog Postgres (`pg_constraint`, termasuk tabel relasi implisit `_BeritaImages` dkk.;
  di-cache per proses) lalu mengecek dengan satu query `EXISTS … OR …` berparameter. Baris perujuk aktif maupun
  soft-delete dihitung — setara perilaku lama (RESTRICT dulu membuat hapus gagal; CASCADE dulu ikut menghapus data lain,
  kini ditolak). Relasi baru otomatis ikut dicek tanpa daftar manual. Rujukan non-FK (URL gambar di isi rich text)
  tidak terdeteksi — sama seperti sebelumnya.
- **`deletedFrom`** = ID submenu sidebar asal (registry `FILE_OWNER_MENU` di `src/lib/sampah/sampah-file-owner.ts`,
  kunci = nama model Prisma pemilik; dikunci test agar semua ID valid). Pemilik tak dikenal / asal tak diketahui → null →
  kelompok **"Lainnya"**. `DELETE /api/fileStorage/delete/:id?from=<menuId>` menerima asal opsional (divalidasi).
- **Berkas di Sampah tidak terlayani publik:** `fileStorage/findUnique/:name` dan `/api/img/:name` → 404 (gambar
  tanpa baris FileStorage tetap dilayani; gagal baca DB di `/api/img` → dicatat & tetap dilayani); pustaka file admin
  (`fileStorage/findMany`) mengecualikannya. Pratinjau admin lewat endpoint terjaga
  `GET /api/pengaturan/sampah/:id/pratinjau` (`Cache-Control: private, no-store`), bukan dengan melonggarkan jalur publik.
- **Adapter entitas koleksi** (`_lib/pengaturan/sampah/sources/`): dokumen DAK, dokumen APBDes, foto galeri BUMDes, dan
  dokumen perencanaan yang soft-delete tampil sebagai item `jenis: "dokumen"` dengan judulnya. Pulihkan = aturan domain
  (DAK & APBDes lewat `pulihkanDokumenFolder` yang juga dipakai panel sampah DAK — perilaku identik; foto BUMDes ke posisi
  terakhir, maks 50; perencanaan aktif lagi). Hapus permanen = baris entitas → baris FileStorage → objek MinIO, berkas
  dilewati bila masih dirujuk (mis. salinan dokumen DAK di program lain). Berkas milik entitas soft-delete dikecualikan
  dari item berkas agar tidak tampil dobel.
- **Retensi:** `SAMPAH_RETENSI_HARI = 30` (`src/lib/sampah/sampah-retensi.ts`, satu sumber; `DAK_SAMPAH_RETENSI_HARI`
  default mengikutinya, env DAK tetap bisa menimpa untuk item DAK). Purge = `deletedAt < now − retensi`.
- **Scheduler in-app** (`src/instrumentation.ts` → `src/lib/sampah/sampah-scheduler.ts`): runtime nodejs saja, purge
  5 menit setelah start lalu tiap 24 jam, penanda `globalThis` mencegah timer dobel saat hot reload, timer `unref()`,
  dilewati saat `next build`. Saklar `SAMPAH_PURGE_SCHEDULER=on|off` (kosong = on hanya di production). Error dicatat
  dengan konteks; log `info` hanya jumlah. **Keterbatasan:** hanya jalan selama server hidup (server mati berhari-hari →
  purge tertunda sampai start berikutnya); setiap instance menjalankan purge sendiri (aman karena idempoten, tetapi kerja
  dobel bila di-scale >1 instance).

## Kontrak `/api/pengaturan/sampah` (khusus role 0/1, guard di handler)
`SampahItem = { id: "file:<fileId>" | "<sumber>:<id>", jenis: "file" | "dokumen", judul, mimeType, kategori: "image" |
"document" | "audio" | "other", ukuran: number | null, pratinjauUrl: string | null, dihapusPada: ISO, sisaHari,
asal: { kelompokId, kelompokNama, menuId | null, menuNama | null } }`. Sumber: `file`, `dak`, `apbdes`, `bumdes-foto`,
`perencanaan`.

| Method | Path | Respons |
|---|---|---|
| GET | `/?kelompok=<sectionId\|semua\|lainnya>&page=1&limit=20&cari=` | `{ success, data: { items, counts: { semua, [kelompokId] }, kelompok: { id, nama }[], page, limit, total } }`. `kelompok` = section sidebar (urutan sidebar) + Lainnya, selalu lengkap; `counts` selalu memuat semua kelompok (0 bila kosong) dan mengikuti `cari`. Urut `dihapusPada` terbaru. `limit` 1–100, `page × limit` ≤ 5000. |
| POST | `/:id/pulihkan` | `{ success, message }`. 404 tidak di Sampah, 409 bentrok (DAK/APBDes/galeri penuh). |
| DELETE | `/:id` | Hapus permanen → `{ success, message }`. 404 tidak di Sampah, 409 berkas masih dipakai. |
| DELETE | `/?kelompok=<id\|semua>` | Kosongkan (kelompok **wajib**) → `{ success, message, data: { dihapus } }`. |
| GET | `/:id/pratinjau` | Isi berkas (Range didukung), `private, no-store`; 404 bila tidak di Sampah. |

Error: `{ success: false, message }` dengan 400/401/403/404/409.

## UI (2026-11-13)
- Halaman **Pengaturan → Sampah** (`/admin/pengaturan/sampah`, submenu `pengaturan.sampah`, guard `canManageSampah`):
  bar tab per kelompok ber-jumlah dari `counts`, cari debounced, Pulihkan, Hapus permanen & Kosongkan (modal konfirmasi),
  pratinjau lewat `pratinjauUrl`. Pola tampilan di `docs/DESIGN.md` (§7 Sidebar Admin & §11).
- **Kosongkan dinonaktifkan saat ada kata kunci cari**: `counts` mengikuti `cari`, sedangkan `DELETE /?kelompok=` menghapus
  seluruh kelompok — jumlah di modal konfirmasi akan menyesatkan.
- **Pustaka File** (`/admin/images`) kini benar-benar memindahkan berkas ke Sampah. Panggilan lama
  `ApiFetch.api.fileStorage.delete({ id })` tidak pernah sampai ke route: Eden menganggap segmen `delete` sebagai method
  (→ `DELETE /api/fileStorage`). Klien memakai `hapusBerkasKeSampah(id, from?)` (`src/lib/file-storage-delete.client.ts`,
  fetch biasa). Bug yang sama di pembersihan berkas yatim galeri BUMDes (`.delete({ id }).delete(...)` → TypeError) juga
  dialihkan ke helper ini dengan `from=ekonomi.bumdes`.

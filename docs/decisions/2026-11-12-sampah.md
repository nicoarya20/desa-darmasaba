# Sampah per fitur koleksi + hapus berkas permanen di menu lain

Tanggal: 2026-11-12 · Dikoreksi: 2026-11-13 (sebelum 0.1.263 dirilis; migrasi `20261112210000_sampah_file` dibatalkan)

## Keputusan
- **Sampah hanya untuk 4 fitur koleksi** yang item-nya bisa dipulihkan UTUH: **Dokumen DAK, Dokumen APBDes, Galeri
  foto BUMDes, Dokumen Perencanaan**. Entitasnya sudah soft-delete (`isActive=false` + `deletedAt`) dan berkasnya tetap
  aktif selama di Sampah. Tiap fitur punya **panel Sampah sendiri** di halamannya; **tidak ada** menu Sampah global.
- **Alasan koreksi (keputusan user):** rancangan awal (0.1.263, belum dirilis) memindahkan berkas dari menu mana pun ke
  halaman Pengaturan → Sampah. Memulihkan foto/berkas berita, potensi, dst. tanpa data induknya (yang sudah terhapus
  permanen) tidak berguna, dan menu Sampah global memberi kesan semua konten bisa dipulihkan dari sana.
- **Menu lain hapus permanen, urutan aman.** `removeStoredFile(file, owner)` (`_lib/fileStorage/_lib/removeStoredFile.ts`)
  menghapus permanen lewat `purgeStoredFile`: baris FileStorage dulu, lalu objek MinIO. Dipanggil **setelah** operasi
  DB record sukses (pola bug Maskot: update gagal → berkas lama tetap utuh). Tidak melempar; gagal dicatat dengan konteks
  `owner` + id. `owner` (nama model Prisma) hanya untuk log. Dipakai ±40 handler del/updt, `removeReleasedFiles`
  (gambar utama + galeri/lampiran m2m yang dilepas), `DELETE /api/fileStorage/delete/:id` (Pustaka File; query lama
  `from` diabaikan), dan `DELETE /api/img/:name`.
- **Berkas yang masih dirujuk tidak dihapus.** `isFileReferenced` (`fileReferences.ts`) membaca semua FK yang merujuk
  `FileStorage` dari katalog Postgres (`pg_constraint`, termasuk tabel relasi implisit `_BeritaImages` dkk.; di-cache per
  proses) lalu mengecek dengan satu query `EXISTS … OR …` berparameter. Baris perujuk aktif maupun soft-delete dihitung —
  berkas dokumen koleksi yang sedang di Sampah tidak ikut terhapus oleh menu lain. Pustaka File → 409. Rujukan non-FK
  (URL gambar di isi rich text) tidak terdeteksi.
- **Tidak ada Sampah tingkat berkas.** `FileStorage` tidak punya kolom asal/indeks Sampah; `fileStorage/findUnique`,
  `/api/img/:name`, dan pustaka file (`fileStorage/findMany`) melayani berkas apa adanya tanpa filter Sampah.
- **Adapter entitas** (`_lib/sampah/sources/`): `createJudulEntitySource` (DAK, APBDes, Perencanaan) dan
  `fotoBumdesSampahSource`. Pulihkan = aturan domain: DAK & APBDes lewat `pulihkanDokumenFolder` (folder asal bila masih
  aktif, selain itu "Umum", di akhir folder; bentrok berkas/batas → 409) — sama dengan panel sampah DAK; foto BUMDes ke
  posisi terakhir (maks 50 → 409); perencanaan aktif lagi apa adanya. Hapus permanen = baris entitas → FileStorage →
  objek MinIO, berkas dilewati bila masih dirujuk (mis. salinan dokumen DAK di program lain).
- **Retensi:** `SAMPAH_RETENSI_HARI = 30` (`src/lib/sampah/sampah-retensi.ts`, satu sumber; `DAK_SAMPAH_RETENSI_HARI`
  default mengikutinya, env DAK tetap bisa menimpa untuk item DAK). Daftar hanya memuat item `deletedAt > now − retensi`;
  purge = `deletedAt < now − retensi`.
- **Purge** `purgeSampah({ now, dryRun })` (`_lib/sampah/sampah.purge.ts`) untuk 4 sumber (`SAMPAH_SOURCES`), dipaging
  per 100 ID; log `info` hanya jumlah. Panel DAK tetap membersihkan dokumen kedaluwarsa programnya secara lazy lewat
  jalur hapus permanen yang sama (`destroySafely`).
- **Scheduler in-app** (`src/instrumentation.ts` → `src/lib/sampah/sampah-scheduler.ts`): runtime nodejs saja, purge
  5 menit setelah start lalu tiap 24 jam, penanda `globalThis` mencegah timer dobel saat hot reload, timer `unref()`,
  dilewati saat `next build`. Saklar `SAMPAH_PURGE_SCHEDULER=on|off` (kosong = on hanya di production). **Keterbatasan:**
  hanya jalan selama server hidup; setiap instance menjalankan purge sendiri (aman karena idempoten, kerja dobel bila >1).

## Kontrak `/api/sampah/:sumber` (khusus admin role 0–4, guard `guardAdmin` di handler)
`sumber` ∈ `dokumen-apbdes` | `foto-bumdes` | `dokumen-perencanaan` (`SAMPAH_SUMBER` di `src/lib/sampah/sampah-item.ts`).
DAK **tidak** lewat sini — tetap endpoint panel sampah DAK (`/api/landingpage/desaantikorupsi/:id/sampah`, dst.).

`SampahItem = { id /* id baris entitas */, judul, mimeType, kategori: "image" | "document" | "audio" | "other",
ukuran: number | null, pratinjauUrl: string | null /* FileStorage.link */, dihapusPada: ISO, sisaHari,
folderNama: string | null }`.

| Method | Path | Respons |
|---|---|---|
| GET | `/:sumber?scopeId=&page=1&limit=20` | `{ success, data: { items, total, page, limit, retensiHari } }`, urut `dihapusPada` terbaru. `scopeId` wajib untuk `dokumen-apbdes` (= `apbdesId`), diabaikan sumber lain. `limit` 1–100. |
| POST | `/:sumber/:id/pulihkan` | `{ success, message }`. 404 tidak di Sampah, 409 bentrok (folder/galeri penuh, berkas sama). |
| DELETE | `/:sumber/:id` | Hapus permanen → `{ success, message }`. 404 tidak di Sampah. |

Error: `{ success: false, message }` dengan 400 (sumber/scopeId/paging tidak valid), 401/403, 404, 409.

## UI
- Panel Sampah per fitur memakai kontrak di atas; logika tampilan murni bersama di
  `src/app/admin/(dashboard)/_com/sampah/sampah-item.logic.ts` (badge sisa hari, info item, paging, teks konfirmasi).
- **Pustaka File** (`/admin/images`) menghapus permanen lewat `hapusBerkas(id)` (`src/lib/file-storage-delete.client.ts`,
  fetch biasa). Panggilan lama `ApiFetch.api.fileStorage.delete({ id })` tidak pernah sampai ke route: Eden menganggap
  segmen `delete` sebagai method (→ `DELETE /api/fileStorage`). Bug yang sama di pembersihan unggahan yatim galeri
  BUMDes (`.delete({ id }).delete(...)` → TypeError) juga memakai helper ini.
